# Working on this repo

- Two branches: `main` = the website (Vercel deploys it); `android` = `main` + Capacitor (`android/`, `capacitor.config.ts`, `.github/workflows/android.yml`) building the APK on GitHub (release `android-latest`). Change shared code on `main`, then merge `main` into `android`. Vercel ignores the `android` branch (`vercel.json` there).
- Phone-friendly is required: check a 390px-wide layout for any UI change, in light and dark (every colour is a CSS variable in `src/index.css`, read by `tailwind.config.js`).
- Keep the Guide (`src/pages/Guide.tsx`) up to date with user-visible changes, in plain everyday words.
- Duke Energy has no public API: `server/duke.ts` copies the phone app's calls (as in github.com/hunterjm/aiodukeenergy). Login is Auth0 with a CAPTCHA, so the user logs in on Duke's page; the website asks them to paste the address Duke lands on (`https://login.duke-energy.com/ios/...?code=`), the Android app catches it in its own WebView (`DukeLoginPlugin.java`). PKCE verifier is made on the device (`src/lib/pkce.ts`). Tokens live in Redis `de:login`; refreshes take a lock (`de:lock`) because Auth0 rotates refresh tokens.
- Usage is cached per chunk (`de:u:...`): days older than 3 days 60 days, recent ones 30 minutes. Daily requests go month by month, hourly week by week.
- Server imports end in `.js` (Vercel runs `api/` as Node ESM without bundling). `npm run dev` serves `api/*.ts` too (`vite.config.ts`).
- Every API call needs `APP_ACCESS_TOKEN` (header `X-Access-Token`): the Duke login is stored on the server.
- 🔔 Alerts: Vercel cron (`vercel.json`, 13:00 UTC daily) → `GET /api/alerts` (`server/alerts.ts`): day ≥ `alerts.pct` above the 14-day average, month heading over the goal, or Duke login lost → ntfy.sh topic. Each day/month judged once (`de:al:*`, set NX). Cron calls are recognised by `CRON_SECRET` (if set) or the vercel-cron user agent. Last 20 sent in `de:sent`.
- 💡 Insights (`src/pages/Insights.tsx`, maths in `src/lib/insights.ts`, on the device): weather = degree-day fit (base + heat × below B + cool × above B, B 50–72 °F best fit) on 13 months of daily data (same request as Months); plan check = last 56 days hourly priced on `settings.plan` (presets are examples, not real tariffs).
- 🚗 Cars (`settings.ev`): charging is found in hourly data by `findCharging` (`src/lib/insights.ts`, shared with the server): hours ≥ max(2.5, kW/2) above the day's 40th-percentile hour, neighbours ≥ 1.5 join, sessions need ≥ 2 h or one hour ≥ 80% of the charger. Used in Insights, Hours, and alerts (`excludeFromAlerts`: the high-day check uses house = daily − car).
- `CRON_SECRET` can only be a Vercel env var (Vercel's cron sends it); Settings makes one to copy and shows `status.cronSecret`.
- 💲 Deals (`src/pages/Deals.tsx`, `api/offers.ts`, `server/offers.ts`): PUCO Energy Choice Ohio apples-to-apples page for Duke Energy Ohio residential (TerritoryId=4) parsed as HTML (offers + Duke's Price to Compare), cached 12 h in `de:offers`. Offers priced on the last 365 days (same 13-month request as Months) vs `settings.supply` (rate 0 = Duke's PTC). "Safe" = fixed, no intro rate, term ≥ 6, cancel fee ≤ $100.
- Duke Energy Ohio official rates in `src/lib/tariffs.ts` (PUCO Electric No. 19, sheets 30 & 32, eff. 2023-01-03): Rate RS distribution $0.039693/kWh vs Rate TD-CPP discount (0–5 every day) $0.030884, off-peak $0.038605, summer (May–Sep) weekday 2–8 PM on-peak $0.057908, critical peak $0.096514 (≤10 days, not modelled). Generation riders are the same per kWh, so `tdcppPlan` = your all-in price ± the distribution difference. Plans have `summerOnly`. Deals → ⚡ CarsCard estimates a year: hourly shape from 8 weeks, totals/summer share from 365 days. Re-check the tariff PDF when Duke files a new rate case.
- Do not add automated tests unless asked.
- `android` branch only: `src/components/AppUpdate.tsx` (update banner from the GitHub release, mounted in `src/main.tsx`), `UpdatePlugin.java`, `DukeLoginPlugin.java` + `LoginActivity.java`, the sideload keystore (fixed key so new APKs install over old ones).
